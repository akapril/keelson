# Native mobile credential vault

Rust-only Tauri 2 plugin. Android stores the host and bearer token together in AES-256-GCM ciphertext, using a non-exportable key generated by `AndroidKeyStore`. Hardware backing depends on the device; this plugin does not claim StrongBox or biometric protection. It never logs secrets and has no JavaScript invoke handler or webview permissions.

## Integration

In the mobile crate:

```toml
tauri-plugin-mobile-vault = { path = "plugins/mobile-vault" }
```

Register `.plugin(tauri_plugin_mobile_vault::init())` on the Tauri builder. The plugin build script adds its `android` library; Rust registers `com.keelson.mobilevault.MobileVaultPlugin`. No generated Android app edits are needed.

```rust
use tauri_plugin_mobile_vault::{Credentials, MobileVaultExt};
// Run these synchronous operations on a worker, not the Android UI thread.
app.mobile_vault().save(Credentials { host, token })?;
let credentials = app.mobile_vault().load()?;
app.mobile_vault().delete()?;
```

The caller must validate host/token before save and after load, verify restored credentials with the server, save before reporting pairing success, and erase on disconnect/401. Network errors must preserve the vault. This layer performs no network operations. Corrupt ciphertext, invalidated/missing keys, and invalid decoded payloads are erased and produce a sanitized read error so the caller can return to pairing. Storage failures propagate; never report pairing success after a failed write.

Non-Android methods return `VAULT_UNAVAILABLE`; the caller must explicitly use its memory-only path on iOS/desktop. There is no plaintext fallback.

## Storage decision

Approved deviation from the initial pairing spec: encrypted shared preferences plus XML backup exclusions were replaced with an `AtomicFile` in `Context.noBackupFilesDir`. Android excludes this directory from Auto Backup and device transfer. Temporary and recovery files remain in that same directory. The Keystore key is app-private and non-exportable. A restored app installation therefore cannot recover a transferable token from a backup.

Envelope: version byte `1`, 12-byte fresh random IV supplied by the cipher, ciphertext plus 128-bit GCM tag. Constant AAD is `keelson.mobile-vault.v1`. Host and token are authenticated together. Writes flush and sync before atomic completion and verify the resulting ciphertext. Delete removes both the encrypted file and Keystore alias.

## Verification

The standalone JVM regression in [VaultCipherTest.kt](android/src/test/java/com/keelson/mobilevault/VaultCipherTest.kt) checks encrypted roundtrip, fresh IVs, no plaintext marker, tamper rejection, truncated data, and wrong-key rejection. [test-cipher.ps1](test-cipher.ps1) runs it using the local cached Kotlin 2.0 compiler and Java (no SDK download). Its cache discovery is intended for this development environment.

[VaultStoreTest.kt](android/src/androidTest/java/com/keelson/mobilevault/VaultStoreTest.kt) is an Android instrumentation test for actual Keystore persistence across store instances, encrypted disk content, corrupt-file recovery, and deletion. Run the plugin module's `connectedDebugAndroidTest` in the generated Android Gradle project with an attached emulator/device. This is separate from the JVM cipher regression; passing the latter does not prove device Keystore behavior or a whole-app restart.
