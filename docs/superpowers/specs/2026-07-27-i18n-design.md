# Keelson 界面国际化 (i18n) 设计

> 状态：设计已确认，待写实现计划。日期：2026-07-27。

## 目标

让 Keelson 的用户可见文案支持中文 / 英文双语切换，覆盖 React 界面、Rust 侧托盘菜单与系统通知。首次启动跟随操作系统语言，用户手动切换后持久记住。

## 非目标

- 不国际化开发用日志（Rust `log`/`println` 与前端 `console`）。
- 不国际化中文源码注释（项目规范用中文注释，保留不动）。
- 不新增第三种语言；架构为多语言预留，但本期只交付 `zh` / `en`。
- 不做服务端（PocketBase）数据内容的翻译。

## 语言集与默认

- 支持语言：`zh`（简体中文）、`en`（英文）。
- 回退语言：`en`（`fallbackLng`）。
- 首次启动检测顺序：`localStorage` → `navigator.language`。中文系统环境 → `zh`，其余 → `en`。
- 用户手动切换后写入 `localStorage`，后续启动优先读取。

## 架构

前端 react-i18next 统管 UI 文案；Rust 侧用一份轻量中英映射管托盘/通知；两者经一条 Tauri command (`set_locale`) 保持语言同步。

### 前端文件结构

```
src/i18n/
  index.ts                 # i18next 初始化
  locales/
    zh/common.json         # 跨页复用（按钮、通用动作、状态词）
    zh/sessions.json
    zh/board.json
    zh/settings.json
    zh/calendar.json
    zh/reading.json
    zh/memory.json
    zh/ai.json
    zh/inbox.json
    en/…（与 zh 同名同结构）
```

- `index.ts` 配置：`supportedLngs: ['zh','en']`、`fallbackLng: 'en'`、`detection: { order: ['localStorage','navigator'], caches: ['localStorage'] }`、`interpolation.escapeValue: false`（React 已防 XSS）。
- 依赖：`i18next`、`react-i18next`、`i18next-browser-languagedetector`。

### 命名空间

按 `src/features/*` feature 边界切分命名空间（`common` + 每个 feature 一个）。分批迁移时一个 namespace 一批，互不干扰。组件通过 `useTranslation('board')` 取本 feature 命名空间。

### key 约定

- 语义化英文点号命名：`board.task.create`、`settings.language.followSystem`。
- 不使用中文原文作 key。
- 插值用具名占位：`t('session.count', { n })` → `"共 {{n}} 条会话"` / `"{{n}} sessions"`。

### 语言切换入口

`src/features/settings/LanguageSection.tsx`，复用现有 Section 组件模式（与 `ProjectDefaultTabSection` 等一致）。提供三选一：`跟随系统 / 中文 / English`。选「跟随系统」时清除 `localStorage` 语言键并回落到检测。

### Rust 侧

```
src-tauri/src/i18n.rs
```

- 维护内存态 `current_locale` 与一份 `key → { zh, en }` 映射，仅覆盖托盘菜单与系统通知这几条文案。
- 新增 Tauri command `set_locale(locale: String)`：更新 `current_locale`，并按新语言**重建托盘菜单文案**。
- 系统通知发送时按 `current_locale` 查映射取文案。
- 现有硬编码中文（如 `"显示 Keelson"`、`"退出"`、通知标题/正文）改为查映射。

## 数据流

- **启动**：i18next detector 定 locale（localStorage 优先，否则 `navigator.language`）→ i18next 就绪渲染前端 → 前端 `invoke('set_locale', { locale })` 告知 Rust，托盘按该语言构建。
- **切换**：`LanguageSection` → `i18n.changeLanguage(next)` + 写/清 localStorage → `invoke('set_locale', { locale })` → Rust 即时重建托盘菜单。

## 迁移策略

242 个前端文件含中文，不可一批完成。分层推进，每层独立可测：

1. **地基**（先行）：安装依赖、`src/i18n/index.ts`、`common` 命名空间、`LanguageSection`、Rust `i18n.rs` + `set_locale` 桥、启动接线。跑通端到端切换（common 文案 + 托盘随语言变、刷新保持）。
2. **逐 feature 迁移**：按命名空间一批一个 feature（sessions → board → settings → calendar → reading → memory → ai → inbox …），抽取该 feature 的 UI 展示串到 `zh/<ns>.json` 并产出 `en/<ns>.json` 初版，组件改用 `t()`。
3. 每批只动 UI 展示串，中文注释与非展示字符串（如日志、内部 key）不动。

英文译文由实现方产出初版，用户后续可润色。

## 测试

- **前端**：i18n 初始化的检测顺序与回退（localStorage 命中、navigator 回退、缺失 key 回退 `en` 不崩）单测；每批迁移挑关键组件做双语渲染断言。
- **Rust**：`set_locale` 更新状态、映射查表（含未知 key 回退）单测；托盘重建 smoke 测试。

## 成功标准

设置里切换语言 → 全 UI + 托盘菜单 + 系统通知随之切换 → 重启后保持上次选择 → 任一缺失 key 静默回退英文、不崩溃。

## 全局约束

- 中文源码注释保留不动，只抽取 UI 展示文案。
- 不硬编码颜色/主题（沿用现有中性主题 CSS 变量约定）。
- store 写失败重抛、调用点 toast（沿用现有约定）。
- 内部标识符、localStorage 功能键、hook 标记、`com.rework.app` 等内部代号一律冻结，不随本期改动。
