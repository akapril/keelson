# iPhone / Android 手机接手任务设计

日期：2026-11-11
状态：原 PWA 路线草案已被用户确认的 Tauri 2 Android/iOS App 路线取代。下文保留为 Web fallback 与后续通知目标设计的参考，不代表当前实现范围。

当前执行计划：[Tauri Mobile P1](../plans/2026-11-11-tauri-mobile-p1.md)。第一阶段为独立本地 UI + 受限原生 HTTPS 桥，连接电脑、配对、会话列表/记录查看；不加载远程页面授予本机能力，不编译桌面 sidecar。后续依次推进原终端接管、原生推送/深链接、iOS/Android 真机验收。

## 目标与平台

在已有 PWA + Tailscale HTTPS 上，实现：电脑产生需要关注的事件 → 手机收到通知 → 点击定位原对象 → 查看上下文 → 继续处理。iPhone 与 Android 同为目标平台。

- iPhone：iOS 16.4+，添加到主屏幕的 Web App，由用户点击申请通知权限。普通浏览器标签页不作为 iOS 锁屏推送的承诺环境。
- Android：支持 Service Worker、PushManager、Notification 的 Chrome 环境；覆盖浏览器与已安装 PWA 的入口，安装提示按能力显示。
- 两端都检查 HTTPS、通知权限和订阅状态。支持性由能力检测决定，不只依赖 UA。
- 手机收到通知与能连接电脑是两个独立状态。电脑离线或 Tailscale 未连接时保留目标、显示可重试状态。
- 本轮不引入原生客户端、自建中继、自动批准或全 CLI 状态推断。

## 对象身份与导航约定

通知目标使用一个有类型的对象，而不是用标题或路径猜测目标：

```ts
type AttentionTarget =
  | { kind: "terminal"; source: "web" | "desktop"; terminalId: string; instanceId: string }
  | { kind: "agent-run"; taskId: string; runId: string };
```

terminalId 用于定位注册表条目，instanceId 标识一次进程生命周期，进程重新启动后必须更换。source 区分两个注册表。已有 CLI 会话 ID 不能替代 instanceId。

同源入口使用 /?attention=<encoded-target>，encoded-target 是 URLSearchParams 编码的 JSON。URL 不携带 token、命令或项目绝对路径。解析时限定目标种类、字段长度及有效标识符；非法、未知目标显示通知列表及说明，不执行命令。

WebApp 在配对、认证及功能配置就绪后消费目标，优先于 localStorage 的上次 tab。重新配对过程中保留目标；解析失败可回通知列表。Service Worker 只接受同源受支持入口，复用同源窗口；导航失败时尝试新开窗口。

服务端根据认证和能力开关解析对象，返回元数据与 available/exited/missing/disabled 状态。客户端收到的项目路径不得反过来成为新进程创建指令。

## 终端处理

新增仅连接已有实例的连接模式，校验 source + terminalId + instanceId。在取得现有进程句柄时完成身份核对，避免先查存在、后连接之间进程重建导致误接。该模式不存在 open/resume 分支。

第一阶段为 Web PTY 完成这一链路。桌面 PTY 在增加可安全共享的输出订阅、历史回放和输入桥接之前，通知显示“该终端暂不能在手机接管”，不得另起同名 CLI 冒充原终端。第二阶段在同一通知协议下实现桌面桥接；外部系统终端不在本轮自动接管范围内。

退出或不存在：展示状态，并在可找到历史会话时提供查看记录入口。任何恢复会话操作都由用户单独点击触发，明确会创建新运行实例。

保留现有输入方式。断线期间发送不应静默成功；返回明确的未发送状态，不排队自动重放输入，以免重复执行命令。

## 受管任务处理

notify_decision 的调用者传入 taskId/runId。持久化通知和推送关联同一对象。Web 增加只读运行结果视图，展示任务、状态、结果摘要或受阻原因，按现有权限提供相关记录入口。

第一阶段不承诺手机合并代码或批准任务；需要桌面处理的操作明确提示。不存在/已删除的运行记录给出说明，不跳到不相关的任务。

## 推送语义与诊断

- BEL 只表达“需要关注”，不表达已完成；受管 review 才显示完成待审。
- 沿用终端按实例冷却，通知携带事件标识用于展示去重。冷却不能跨不同终端共享。
- 不因任意窗口可见就静默吞掉推送；优先保证每次实际 push 有可见通知。精确前台抑制只有在目标视图确认消费事件时才启用，并验证浏览器要求。
- 推送状态区区分：不支持、需要安装、非 HTTPS、未授权、权限拒绝、已订阅、订阅不可用。
- 测试按钮成功文案为“已提交到推送服务”，不能声称手机已收到。401/403、429、5xx 与网络失败可诊断；404/410 清理失效订阅。
- 日志不得输出完整推送 endpoint、私钥、token 或任务正文。

## 实施顺序

1. 固定现有未提交推送工作的测试基线，保存逐文件差异；只处理本任务涉及内容，不包含日历等无关改动。
2. 实现有类型目标解析、配对后继续导航、同源 SW 点击处理，以及功能关闭/失效提示。
3. 为 Web PTY 添加实例身份、元数据解析与仅附着连接；打通双会话通知定位和手机输入。
4. 让受管通知携带运行标识，增加 Web 只读结果定位。
5. 完成桌面 PTY 桥接后，再承诺桌面终端原进程接管。
6. 完善两端安装/授权指引和推送诊断，完成真机验收。

各阶段独立测试后再提交。新功能是否发布单独判断，不复用此前 AppImage 发布授权。

## 验收

自动化：目标编码/解析往返；非法字段/跨源链接拒绝；认证后目标恢复；能力关闭；两个会话分别定位；实例重建时旧通知拒绝连接；仅附着模式永不创建进程；推送错误分类；run 已删除；断线输入明确失败。

真机矩阵每端分别记录机型、系统/浏览器版本、安装模式、网络与时间戳：

| 场景 | iPhone 主屏幕 Web App | Android Chrome / PWA |
|---|---|---|
| 用户触发安装/授权，发送测试推送 | 必测 | 必测 |
| 锁屏、退后台、冷启动点击通知 | 必测 | 必测 |
| 两会话交错事件，点击各自通知 | 必测 | 必测 |
| 中文输入、换行、Enter、Ctrl-C、软键盘遮挡 | 必测 | 必测 |
| 电脑离线/Tailscale 断开后重试 | 必测 | 必测 |
| 配对过期、功能关闭、进程退出与重启 | 必测 | 必测 |
| Agent 完成/受阻通知查看对应结果 | 必测 | 必测 |

正常网络连续 10 次每端各自通过：记录事件产生、推送服务接受、手机展示、点击定位时间；不得串会话或重复发送输入。推送受 OS/网络调度影响，不承诺固定送达秒数。

桌面浏览器和模拟器测试不替代 iPhone/Android 真机锁屏推送。没有设备证据时状态保留“待真机验收”，不得写成双端已验证。

## 设计复核

已按源码修正三个假设：Web 未实现 /inbox 导航；默认 WS 可创建进程；桌面/Web PTY 不同。身份、仅附着连接、失效提示是通知直达原会话的前置条件。按上述阶段可逐步交付，只有全部目标场景验收后才能宣称双端手机接手流程完成。
